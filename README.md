# SML Dashboard — เชื่อมข้อมูลจริง

เปิด http://localhost:3000 หน้าเว็บใช้ข้อมูล PostgreSQL เท่านั้น ไม่มีโหมดตัวอย่างแล้ว

## รัน

ใช้ Node.js 22 ขึ้นไป รัน `npm install` และสร้าง `.env` จาก `.env.example` เฉพาะครั้งแรก จากนั้นรัน `npm start` ใน PowerShell

สำหรับ Intranet ให้ตั้ง `HOST=0.0.0.0` และ `PORT=3000` ใน `.env` (หรือใช้ค่าดีฟอลต์นี้) แล้วเปิดจากเครื่องอื่นด้วย `http://<IP-เครื่องที่รันเซิร์ฟเวอร์>:3000` เช่น `http://192.168.1.25:3000` ต้องอนุญาตพอร์ต 3000 ใน Windows Firewall ของเครื่องเซิร์ฟเวอร์ด้วย

## นิยามที่ตรวจสอบกับ SML

- KPI ยอดขายและกราฟรายวันอ้างอิง SQL ต้นฉบับของรายงาน 4007 (มูลค่าสุทธิของเอกสารตามวันที่): ic_trans.total_amount, trans_flag=44, last_status=0 และเวลา 00:00–23:59 จำนวนบิลนับ header ตามเงื่อนไขเดียวกัน
- กราฟคลังและ Top 5 อ้างอิงรายการของรายงาน 4014: ic_trans_detail.sum_amount, trans_flag=44, last_status=0, วันที่ที่เลือก และรหัสสินค้าไม่ว่าง แล้วจัดกลุ่มตามคลังหรือสินค้า/หน่วย
- ยอด header และรายการอาจต่างกัน หน้าเว็บแสดงส่วนต่าง ไม่เฉลี่ยหรือบวกยอดสมมติเพื่อทำให้เท่ากัน ใช้ sum_amount ตามรายงานโดยไม่คำนวณ VAT เพิ่มเอง
- ทั้งสองชุดยังไม่หักเอกสารรับคืน/ลดหนี้ flag 48 จึงไม่ใช่ยอดของรายงานสุทธิหักคืนอื่น
- สินค้าขายดีแสดงทุกรายการในช่วงวันที่เลือก แยกหน่วยนับ สัดส่วนเทียบยอดขายสินค้าทั้งหมดที่ผ่านเงื่อนไข ใช้รายการยอดเงินมากกว่า 0 ที่มีรหัสใน ic_inventory และมีบิลขายไม่ยกเลิกตรงวันที่ ตามช่วงเวลาเดียวกับยอดเอกสาร ไม่รวมรหัสหมายเหตุ กดจำนวนขายเพื่อดูบิลต้นทางได้
- รายการยอดเงินศูนย์/ติดลบ และรายการไม่พบรหัสในทะเบียน/หมายเหตุ แสดงในส่วนแยกตรวจสอบ ไม่สรุปว่ารายการยอดศูนย์เป็นของแถม ยอดรวมเอกสารและยอดรายการรายงาน 4014 ยังคงใช้เกณฑ์เดิม ทั้งหมดไม่หักรับคืน

## การอัปเดต

โหลดใหม่ทุก 60 วินาทีขณะหน้าเว็บเปิด และเมื่อกลับมาที่แท็บ กด Refresh SML เพื่อโหลดทันทีได้ ช่วงกำหนดเองไม่เปลี่ยน วันที่แบบเดือนนี้/ล่าสุดขยับตามวันปัจจุบัน API ไม่ใช้ cache และใช้ SQL statement เดียวต่อครั้ง หากเชื่อมต่อไม่ได้จะล้างกราฟและแสดงข้อผิดพลาด ไม่แสดงข้อมูลจำลองแทน เวลาท้ายหน้าคือเวลาที่ดึงข้อมูลสำเร็จ

## การตรวจสอบ

ตรวจฐาน ski แบบ read-only วันที่ 7 ก.ย. 2026: เทียบทุกวันและยอดรวมกับ SQL ที่ถอดจากรายงาน 4007 ใน sml_fastreport ผ่านช่วง 1–7 ก.ย. และ 1–31 ส.ค. รวมทั้งช่วงไม่มีข้อมูล เทียบยอดคลังและ Top 5 กับ SQL รวมรายการแยกต่างหากตามเงื่อนไข 4014 ผ่าน API ปฏิเสธวันที่ผิดด้วย HTTP 400

รันทวน: node --env-file=.env verify-sml.js โดยใช้ sml-report-4007.xml ที่ถอดไว้ ผล ณ เวลาทดสอบบันทึกใน verification-results.json ยอดเปลี่ยนได้เมื่อมีการบันทึก/แก้ไขบิล

ผลนี้ตรวจเทียบ SQL รายงานในฐาน ยังไม่ได้ตรวจผลพิมพ์ในหน้าจอ SML ด้วยมือ และยังไม่ได้สร้างหน้าเว็บรายงานทั้งหมด 569 รายการ

## การเชื่อมต่อ

ค่า PostgreSQL อยู่ใน `.env` ฝั่ง server ไม่ส่งรหัสผ่านให้ browser เซิร์ฟเวอร์ bind ตาม `HOST` และตั้ง connection เป็น read-only API: GET /api/dashboard?start=2026-09-01&end=2026-09-07 (ไม่เกิน 366 วัน)

หน้าเว็บต้องโหลดผ่าน Backend ใช้อินเทอร์เน็ตสำหรับ Tailwind/Chart.js CDN และฟอนต์ หากจะเปิดใช้งานสาธารณะต้องเพิ่มระบบยืนยันตัวตนและ build CSS ก่อน
